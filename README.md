# Autonomous Civilizations

Server-authoritative Minecraft civilization mod for Minecraft 1.21.1 / NeoForge. The world model is kept separate from Minecraft entities so distant simulation operates without loading chunks.

## Toolchain

- Minecraft 1.21.1
- NeoForge 21.1.251
- Java 21
- Gradle wrapper 8.9

## Build and run

From PowerShell in the project directory:

```powershell
.\gradlew.bat build
.\gradlew.bat runClient
```

The `runClient` task uses the development world under `run/`. Mod diagnostics are written to `run/logs/latest.log` with the `[autociv-diag]` prefix.

## Commands

- `/civ` or `/civ list` - list civilizations
- `/civ history [civilization]` - browse the latest 40 saved historical events across the world or for one civilization
- `/civ lod` - inspect the nearest cities and their current distance-based physical simulation tier
- `/civ charter <name>` - found a player-sponsored civilization at a dry, level, natural site at least 512 blocks from existing cities; costs 96 oak logs, 64 cobblestone, and 24 wheat
- `/civ info <name-or-id>` - show a civilization
- `/civ create <name> [color]` - create a civilization; the name is one word
- `/civ city create <civ> <name>` - create a city at the command source position
- `/civ city addcitizen <civ> <city> <name> <age> [profession]` - add an abstract citizen
- `/civ city resource <civ> <city> <resource> <amount>` - change a city's resource stockpile
- `/civ economy <civ> <city>` - inspect stock, target, price, daily trend, market buy/sell offers, assigned resource regions, and active trade links
- `/civ trade` - inspect persistent trade routes and shipment totals
- `/civ debug` - show compact simulation totals; `/civ debug <civilization>` lists its cities, and `/civ debug <civilization> <city>` opens a concise city report. Use Tab at each argument to select a civilization and then one of its cities.
- `/civ debug years <1-100>` - advance the abstract simulation by that many years for development testing; `/civ debug years` shows progress and `/civ debug years stop` stops the run. This is paced over server ticks so entity AI and world updates can continue.
- `/civ gui` - open live civilization, economy, and citizen-job diagnostics (F8 on the client)
- `/civ job <civ> <city> <citizen-id-prefix> <profession>` - reassign a citizen for simulation checks (permission level 2); profession is any `Citizen.Profession` id, such as `blacksmith`, `engineer`, `doctor`, or `researcher`
- `/civ debug build <civ> <city>` - spend 48 wood and 24 stone to start one house immediately for builder testing (permission level 2)
- `/civ debug facility <civ> <city> <type>` - start a paid facility project for builder testing; the type is suggested in-game (permission level 2)
- `/civ diplomacy` - inspect bilateral relation labels and persistent opinion scores
- `/civ diplomacy <civ>` - inspect one civilization's relationships, opinions, and active treaties
- `/civ diplomacy treaty <civA> <civB> <trade_pact|non_aggression|alliance> <days>` - sign/renew a timed treaty (permission level 2)
- `/civ diplomacy war <civA> <civB>` - declare war and suspend trade shipments (permission level 2)
- `/civ diplomacy peace <civA> <civB>` - end war and create a 360-day peace period (permission level 2)
- `/civ territory` - summarize claimed regions and their resources; `/civ territory <civ>` lists region centers and richness
- `/civ network <civ> [page]` - browse the capital-to-daughter city tree, specialization, tier, parent links, homes, and founding year (40 cities per page)
- `/civ roads <civ>` - inspect completed road corridors between a city's parent and daughter settlements
- `/civ rails <civ>` - inspect operating railway corridors between station-equipped parent and daughter cities
- `/civ simulate` - show current simulation speed, interval, and elapsed abstract time
- `/civ simulate <realistic|fast|debug>` - set and persist the world's simulation speed (permission level 2)
- `/civ tp <civilization>` - teleport to the capital; `/civ tp <civilization> <city>` to select a city (permission level 2)
- `/civ tp <civilization> outpost <rival>` - teleport to that civilization's border camp facing the rival (permission level 2)

Each simulation step advances one abstract day. `realistic` runs every 24,000 server ticks (one Minecraft day), `fast` every 2,400 ticks, and `debug` every 200 ticks. Professions now affect abstract production: farmers, fishers, hunters, and shepherds supply food; lumberjacks supply wood; miners supply stone, iron, and coal; blacksmiths turn iron and coal into tools and weapons; engineers turn wood and stone into building materials. Merchants add trade income, researchers add culture, doctors improve resident health, and guards/soldiers improve city security. The allocator fills shortages and specialist needs while keeping explicitly assigned jobs when possible. Food is consumed, health and food-needs change, and population grows slowly when housing, food reserves, happiness, and security allow it. Persistent starvation and overcrowding can reduce health and eventually remove citizens. A selected historical profile sets the calendar epoch and schedules dated milestones with historical events and state/resource changes.

`/civ debug` includes city-level job counts, completed facilities, active construction progress, and the last simulated day's net changes for food, wood, stone, iron, coal, tools, weapons, and building materials.

Administrative world mutations require command permission level 2. `/civ charter` is a player action with an in-game material/site cost; colony owner actions use their separate server-checked ownership rules. In singleplayer, cheats must be enabled for admin commands that change the world.

The F8 / `/civ gui` screen lists settlements with teleport, market, and test-construction buttons. Its worker tab shows up to 16 physical citizen slots per city, whether each Villager is loaded, the current job state and target block, carried cargo, and buttons for physical jobs. Any abstract profession can be assigned with `/civ job`. Blacksmith and engineer recipes run in the unloaded-city simulation too; their inputs and outputs appear in `/civ economy`. Teleport, job assignment, simulation-speed changes, and test construction require permission level 2. Test construction consumes its normal wood and stone cost.

The city planner starts persistent plans when shortages, low security, population, health, education, or storage pressure justify them. Farm and mine facilities improve matching worker output; warehouses expand stock capacity; markets and roads reduce abstract transport costs; barracks and fortifications improve security and defense; clinics improve resident health; schools speed up education. Plans reserve wood and stone at the start and advance once per simulation day. Their progress and completed counts survive save/load. When a tagged settlement is physically loaded, a builder places completed facilities incrementally from built-in block blueprints; candidate sites must be loaded, level, and free of non-natural blocks, and the builder never requests distant chunks. The facility blueprints are currently built into Java rather than supplied as NBT/Schematic assets. If a player obstructs a site after construction begins, that project waits until the obstruction is cleared. Use `/civ debug facility <civ> <city> school` (or another facility id) to force a project while testing.

Simulation data is stored in the world save as `data/autociv_simulation.dat` and is written by Minecraft's normal world-save process after a command changes state.

## Current boundary

The current implementation includes scheduled abstract production, profession allocation and recipes, food consumption, population growth/decline, persisted simulation speed, world-save persistence, scenario-driven starter world generation, vanilla Villager projection, teleport and commands. The market includes stock-based offers, scarcity and net-stock-trend pricing, daily treasury revenue, distance-aware matching, capacity and treasury limits, and persistent shipment history. A purchase now departs as an abstract shipment: the seller's stock is reserved at departure, the buyer's payment is held in escrow, the ETA depends on distance and is shortened by roads, markets, and trade agreements, and arriving goods are delivered before the seller is paid. In-transit cargo counts against the buyer's demand and storage capacity to prevent duplicate orders. War cancels shipments, returns cargo where capacity allows, and refunds the buyer; partial deliveries settle only delivered goods and refund the rest. The transport margin is recorded as the route merchant's logistics revenue. Shipments and merchant revenue persist across world saves; older saves load with no shipments and zero historical logistics revenue. Caravans are currently represented in the simulation ledger rather than as visible entities. Cities now form a saved capital-to-daughter hierarchy, grow through six population/home tiers, and receive a role based on their region. Agricultural, forestry, mining, trade, and frontier roles change worker allocation, output, and construction priorities. `/civ network <civilization> [page]` displays the hierarchy in pages of 40 cities, including parent, role, tier, housing, and founding year. Older saves load as capitals and unlinked villages; new daughter cities receive specialist roles. City planning covers housing, resource, storage, trade, health, education, and defense projects. Bilateral relations evolve from trade, settlement proximity, and shared historical era, with persisted opinion scores. Sustained cross-civilization trade can autonomously renew trade pacts and lead to non-aggression agreements; admins can also sign timed trade, non-aggression, and alliance treaties or declare wars. At tense or hostile borders, cities within 3,200 blocks can dispatch an abstract garrison to establish opposing forward camps, paying 120 wood, 64 stone, 40 food, and 6 weapons from the supplying city's stock. Camps and their founding days persist. Once both camps remain opposed for 180 days, the standoff automatically becomes war unless a peace, non-aggression, or alliance treaty protects the border. `/civ diplomacy <civilization>` reports camp coordinates and standoff duration. Camps are rendered as fenced wooden watch posts with a central campfire only when their site is already loaded, level, dry, and clear; they never load chunks or replace solid player blocks. Every 30 simulation days, neighboring civilizations at war resolve a supply-backed border engagement. Adult soldiers and guards, military legacy strength, food, weapons, tools, barracks, and fortifications determine readiness and defense. Campaigns consume actual city stock, damage security and happiness, can cause garrison casualties, and append dated events to both civilizations. When a supplied attack breaks the defenses of a non-capital city, the attacker can capture it; the settlement, residents, buildings, and stock stay intact under the new civilization, its capital becomes the new network parent, and any children are reattached to their former capital. Capital cities cannot be captured. The territory grid remains nearest-city influence, so a city's transfer changes its regional owner at the next territory update rather than modeling manual occupation borders.

On the Create World screen, select the Normal world preset and open its settings button. Use `<` / `>` to choose one of the 15 historical profiles. The choice is stored as a world gamerule and that profile is guaranteed to be part of the starting roster. At first server start, the world seed deterministically selects 10-15 distinct civilizations, with capitals at varied distances (roughly 640 to 11,600 blocks). Founding size now scales with distance from the joining player (or world spawn if no player is online): nearby capitals remain small camps, while capitals around 6,000 blocks begin as established towns with larger populations, proportionally larger starting stores and treasury, and completed-home backlogs. Up to six starter homes are placed when the capital chunk naturally loads; established towns use finished house templates instead of packed-mud huts. Further homes remain in the saved construction queue and builders continue them from the town store when the required neighboring chunks and materials are available. No distant chunks are force-loaded. Other cities are founded later by mature capitals rather than appearing at world start.

Nearby capitals start as four small packed-mud and thatch huts beside a shared farm, mine, wood yard, bell town hall, and common chest. Distant capitals start with more residents, resources, and home plans; starts with eight or more residents use finished house templates for their first homes. The terrain and farm irrigation curb are generated only when the capital chunk naturally loads. Every additional house adds one resident place in the abstract model. Builders take physical structural blocks from the town warehouse one blueprint placement at a time; logs, planks, mined stone, stone brick, stairs, slabs and walls cannot come from abstract stock. Clearing, furniture and decorative fixtures are template details. If a block is missing, construction waits and the hall screen shows the exact demand. Residents deliver mined and gathered goods to that chest. Right-click the town-hall bell while holding resources to donate them; valid donations enter the shared stock and raise player trust with the civilization. Torch workers craft torches from chest coal and wood, then light house approaches and low-light points within already loaded chunks. The town hall and chest do not force-load chunks.

At 28 residents/homes plus sufficient food, wood, stone, and treasury, a mature city can send four founders and starter supplies to a daughter city at least 192 blocks away. Founding selects an open site, favors richer resource regions and missing specialties, records the parent and founding year, and gives the new settlement four resident places backed by four homes. The daughter enters the city hierarchy and specializes as an agricultural, forestry, mining, trade, or frontier center. Specialist centers recruit more matching workers, produce up to 30% more of their focus resource, and prioritize matching civic buildings; frontier cities favor barracks and fortifications. Trade centers improve merchant income, while frontier guards improve security more efficiently. The development tier is derived from the lower of housed population and completed homes: outpost, hamlet, village, town, city, or metropolis. Each civilization can hold up to 10,000 cities. Use `/civ network <civilization>` to inspect the parent-child network; add a page number for large empires. Existing vanilla villages are adopted as established civilizations when their villagers load; they start with mature abstract resources and buildings, and their occupied homes count against population growth. Newly generated civilizations and imported villages both continue through the city planner. Nearby cities materialize up to 16 tagged vanilla Villagers plus up to two Iron Golem guards per city; this is a rendering cap, not the abstract population cap. Citizen miners carry an iron pickaxe and mine exposed ore in the bounded mine work zone; guards patrol threats within the settlement radius and prioritize monsters attacking a Villager. Tagged Villager deaths remove the corresponding abstract citizen. No chunk tickets are kept or remote chunks requested. Use `/civ debug <civilization>` and `/civ debug <civilization> <city>` to inspect, and `/civ tp <civilization> <city>` to visit cities.

The profiles are historically inspired starting scenarios, not exact reenactments; subsequent outcomes can diverge. Physical farmers, miners, and lumberjacks carry both their abstract economic yield and exact harvested Minecraft items in a bounded, saved citizen pack. They walk to the warehouse and store real wheat, raw ore/coal/cobblestone, and the local tree species; the exact blocks are not replaced by oak logs or other generic items. Pack contents and basic needs survive world saves. The abstract day step updates all five citizen needs; poor sleep and safety affect health, overcrowding lowers comfort, and social ties and the full need average feed mood and settlement happiness. Adult worker output and crafted goods scale with health and need fulfillment, while population growth requires adequate average needs. Housed residents recover some sleep in the abstract simulation; nearby tagged residents also walk to a generated bed at night and recover additional sleep there. The debug worker details show abstract cargo, exact item stacks and each need. Lumberjacks harvest and replant the actual tree species in the generated lumber yard instead of being hard-coded to spruce. Stone-themed templates use gatherable cobblestone so the mine can supply their construction without an unavailable smelting chain. The hall stock readout counts all supported biome timber and stone variants. Guards retain their independent patrol behavior. Delivery waits with any overflow that the stockpile cannot accept, and workers do not destroy a target when their pack lacks room for its harvest. Engineers now use the world's loaded crafting recipes to make a limited reserve of planks, slabs, stairs, composters, crafting tables, chests, doors and fences from items in the shared warehouse while construction is pending. Crafting consumes real chest ingredients and requires room for the output; recipes that would return container items are skipped. The worker debug state shows when an engineer travels to the workshop, crafts, or is waiting for ingredients/storage. Physical AI remains bounded to settlement jobs and does not use vanilla Villager inventories, satisfy needs with world resources, travel between cities, or provide general-purpose construction.

## Civilization traits and remaining roadmap

New historical starts receive two stable traits shown by `/civ info <civilization>`. Traits are derived from the saved scenario id, so no extra save field is needed. Traits affect the actual AI: agricultural states produce more food and favor farms; industrial states extract more raw materials and favor mines/warehouses; trading states earn more merchant income, favor markets/banks and reduce shipment transport costs; scientific states gain more culture and favor schools; defensive and militaristic states favor defenses and perform better in campaigns; expansionist states found daughter cities earlier and favor roads; isolationist states form diplomatic affinities more slowly. They modify priorities and yields rather than overriding shortages, treasury, material, or security requirements.

The original 20-stage outline is not fully complete. Stages 1-2 and abstract cores from stages 3, 5, 8-10, 12-20 are present; several still need their full physical or gameplay layer. These remain partial or outstanding:

- **3-4, economy and professions:** the world ledger trades and assigns jobs, and nearby workers gather real items, but physical jobs are a limited set and do not fully reconcile every unloaded citizen's inventory/work schedule with the ledger.
- **5-7, construction and NPCs:** houses and civic buildings use authored Java templates, not reusable NBT/Schematic assets. Builders place paid blocks incrementally, but the physical layer is not a complete Brain/Schedule/Inventory state machine; jobs pause outside naturally loaded chunks.
- **9-10, diplomacy and territory:** bilateral opinions, treaties, conflicts and resource regions work. Ultimatums, cultural conflict systems and claimed border polygons are not implemented; regional ownership is assigned by nearest settlement.
- **11-13, war, expansion and trade:** wars, captures, city founding and escrowed shipments work abstractly. There are no persistent Army/ArmyUnit/War/Front models, physical battle resolution or visible trade caravans; daughter-site selection uses the abstract region grid rather than scanning terrain.
- **14-15, transport infrastructure:** derived abstract road and railway corridors now change trade distance and delivery timing. Terrain-aware inter-city routes, bridges, connected physical tracks, and obstacle pathfinding remain unfinished.
- **16-20, world and player:** far cities continue mathematically without chunk tickets; nearby entity projection now uses NEAR/MID/FAR/VERY_FAR budgets. Historical events, condition-driven famine/epidemic/golden-age events, trait effects and player-funded founding are present. A full LOD scheduler for batched city simulation, the remaining event types, enlistment/mercenary play and deeper diplomatic player actions remain unfinished.
- **25-26, map and debug:** the F8 diagnostics and town-hall screens exist, but there is no interactive civilization/world map displaying borders, wars, armies, roads, rails and trade traffic.

Stage 14 now has a working abstract road graph derived from persisted city-parent links and completed road buildings. A corridor activates only when both ends of each parent-child link have roads; one, two, and three road levels improve its effective freight distance by 12%, 24%, and 36%. Trade between connected cities uses that corridor distance for price and delivery time. Cities without a complete corridor keep the direct overland fallback, and cross-civilization trade still uses that fallback. `/civ roads <civilization>` reports active corridors and their quality. The graph is derived at use time, so it cannot become stale after a city changes owner or is removed and requires no save migration. Terrain-aware road placement, bridges, pathfinding around obstacles, and physical road blocks between cities remain outstanding parts of Stage 14.

The next major systems are visible shipment/caravan projection and then the much larger military unit model (Stages 11/13). Neither is implied to be complete by abstract trade shipments or diplomatic border camps.

Stage 15 adds abstract railway stations as a city-planned facility. Trading civilizations and trade-role cities prioritize station construction after a market and road network exist. A rail line operates only when both a parent city and its daughter city have completed stations; rail corridors reduce effective freight distance to 42% and trade chooses rail when it beats both the road corridor and direct route. Station buildings have a small authored station-house and platform blueprint. `/civ rails <civilization>` reports operational lines. Lines are derived from saved city hierarchy and station counts, with no save migration; physical tracks between cities and Create integration remain future work.

Stage 16 now gives physical residents distance-based budgets: NEAR cities project up to 16 villagers and 2 guards, MID cities up to 6 villagers and 1 guard, and FAR/VERY_FAR cities keep only abstract residents. When an area drops to a lower tier, excess tagged entities are discarded and their citizen records are unbound; returning closer can materialize them again. The abstract simulation still advances every city so distant wars, production and trade are not frozen. `/civ lod` shows the nearest cities and budgets. Full batching of distant mathematical updates is still future work.

Stage 17 keeps using the existing saved civilization event histories, but `/civ history [civilization]` now merges them into a year-sorted world timeline and displays the latest 40 entries. Stage 18 traits affect both the earlier economic/military planning systems and the new systems: trading civilizations favor stations, scientific civilizations enter golden ages at a lower education threshold, and agricultural civilizations suffer less ongoing famine health loss.

Stage 19 adds persistent, condition-driven famine, epidemic, and golden-age lifecycles. They start and resolve on measurable city conditions rather than random rolls; state markers live in the already-saved civilization history field, while user-facing history hides those markers. Famine and epidemics affect happiness, health and security, and golden ages add culture. More event types such as drought, flood, migration, rebellion and civil war remain future work.

Stage 20 adds `/civ charter <name>` for player-funded founding. It validates a loaded, dry, natural and reasonably flat site at least 512 blocks from existing cities, consumes real starter materials, creates a small capital with three initial workers, claims that capital for its founder and lets the normal planner build its homes. Starting logs, cobblestone and wheat are placed in the actual town-hall warehouse; if that cannot accept them, they do not appear in the city's ledger. The new city is physically generated only in its already-loaded chunk and continues abstractly when unloaded. This does not add enlistment, mercenary contracts, player diplomacy or sabotage gameplay.

## Colony and admin management

The town-hall screen has overview, economy and management tabs and is available by right-clicking the bell or running `/civ hall <city-uuid>`. Players can view relations, happiness, needs, safety, stocks, market offers, active trade routes, inbound/outbound shipment cargo with arrival estimates, resident jobs and the latest event. `/civ trade` lists route history and every shipment currently in transit. An unclaimed town can be claimed with `/civ manage <city-uuid> claim` after earning 25 trust by donating resources and while standing near its loaded town hall. Only the owner can change settings or submit work; the server checks owner UUID, distance, resources and project limits on every mutation.

Residents' nameplates now begin with their civilization name in its RGB faction color, followed by their Russian profession and current activity. The style refreshes when citizen ownership or profession changes. Border outposts are persisted in the world save; when an outpost chunk is already loaded, a small fenced camp is built only on a flat, dry, clear site. `/civ diplomacy <civilization>` shows both camp coordinates and the 180-day standoff timer; a peace or non-aggression treaty removes the camps and prevents automatic escalation.

The owner can set a policy with `/civ manage <city-uuid> priority <food|construction|extraction|trade|defense>` and `/civ manage <city-uuid> strategy <growth|reserves|fortify>`. Jobs use `/civ manage <city-uuid> job <resident-id-prefix> <profession>`. Projects can be queued with `/civ manage <city-uuid> build <building>`, moved using `order <1-based-index> <up|down>`, and canceled with `cancel`. The cost is reserved from the city's abstract stock when queued, and queue order is saved. The planner executes queued projects before automatic building needs. Food/trade priorities influence existing planner choices; extraction and defense weight mine/defense projects; reserves delays discretionary buildings during a food shortage; fortify favors barracks and fortifications. Old saves load with unclaimed cities and the default policies.

Owners can place a persistent recipe job with `/civ manage <city-uuid> craft <minecraft:block_id> <batches>`. Suggestions list block items for which the current world has a crafting recipe; each batch crafts one recipe output. The queue holds up to 32 orders and 64 batches per order. `/civ manage <city-uuid> craftorder <index> <up|down>` changes priority and `craftcancel <index>` removes a job. The engineer gives explicit orders priority over construction demand and automatic workshop reserves, takes ingredients from the town warehouse, and returns crafted blocks there. When a blueprint needs a craftable structural block and stock is empty, the builder publishes that item and the engineer tries its recipe first. Uncraftable materials such as a biome-specific log remain a gathering or donation requirement and appear as a wait state. Ingredients are consumed only when the output fits; recipes that return container items are skipped. Physical materials are paid per placement, so there is no obsolete upfront builder deposit. OPs can use `/civ admin craft <city-uuid> <minecraft:block_id> <batches>` and `/civ admin craftcancel <city-uuid> <index>` without city ownership. The management screen shows both construction and workshop queues and opens the order command from its “Заказ крафта” button.

Press F8 or run `/civ gui` to open the diagnostics/admin screen. Its administration buttons send commands that the server independently gates at permission level 2; creative mode alone grants no privileges. `/civ admin` lists the command interface. It supports day stepping, pause/resume, city rename/move/delete, resident age/job/delete, city resource and welfare edits, civilization treasury/culture, city owner transfer, project completion/cancellation and event history. Deleting a city requires the explicit `CONFIRM` token; already placed blocks are preserved. Moving a city is currently limited to settlements whose physical village has not yet generated, so buildings are never orphaned by an abstract move.

## Residential building templates and asset sources

Physical homes continue to use the existing incremental builder: sites must be naturally clear and in already loaded chunks, construction pauses on player blocks or unavailable chunks, each structural wood or stone placement is paid from the shared town warehouse, and the placement cursor plus current material demand are saved. Construction waits at the missing block and never substitutes an abstract stockpile amount. Blueprint clearing, furniture, beds, doors and decorative fixtures are excluded from structural billing. The authored template set includes starter huts (packed mud and thatch), family homes (local timber frame and pitched/biome roof), farmer cottages (hay details and compost corner), craftsman cottages (stone base, timber frame and workbench detail), and upgraded homes for mature settlements. Variant choice follows the home's resident profession, population and historical era. Available blocks remain basic logs/planks, dirt, hay and mined stone, with biome wood and civilization roof style selection. Houses are Java blueprints in this release; no NBT dependency or schematic asset is bundled.
